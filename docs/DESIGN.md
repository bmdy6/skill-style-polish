# 设计说明

本设计请 Claude Code 当顾问讨论过，代码按下面的规则实现。

## 去噪（denoise.py）
- 直接丢弃：子代理或侧链会话（pi 的 `parentSession`、Claude 的 `isSidechain`），非交互入口（Claude `entrypoint=sdk-*`、Codex `originator=codex_exec`）。
- 逐条打分，分数相加：
  - 前缀模板：长度 >80，归一化后取前 48 字，在 ≥5 个会话、≥3 个不同日期出现 +2；≥20 个会话 +3
  - 近似重复：5 字 shingle 的 Jaccard ≥0.8，且其他会话里有 ≥3 条 +2
  - 结构化排版 +1.5
  - 距上一条 assistant 消息 <2 秒 +2
  - 字数/间隔 >15 字每秒，且长度 >200 +1.5
  - 10 秒内同前缀开出 ≥3 个会话 +3
  - 单消息会话 +1，临时目录 +1，worktree +0.5
  - 人类证据（多轮会话里的短句或回指上文）−1
- ≤15 字的重复短句（"继续"之类）不算模板分，它们本身就是文风特征。也不把语气词、错别字当"人类证据"，否则会形成循环偏差。
- 阈值：≥3 判为 auto，1.5–3 判为 suspect（默认丢弃），其余为 human。一个会话里 ≥60% 是 auto，整个会话丢弃。

## 敏感实体（detect.py → apply_review.py → filter.py）
- 来源基础分：工作目录名 +5，@提及 +4，非公共域名或 GitHub owner +4，驼峰词 +2，全大写 +1，CJK 机构后缀 +3，CJK 人称后缀 +3/+4。
- 合并打分：最高来源分 + 0.5 × 其余来源分之和，再按出现的会话数加分；在 >30% 会话里出现、又不是目录名来源的，−2。
- ≥5 由规则直接脱敏；3–4.9 交 agent 审阅，agent 只看词、类型和计数，不看原文。审阅失败即保守：只有判为 generic_tech 或 common_word 时才保留，其余一律脱敏。
- 档案只存统计量和槽位模板，写盘前过 `check.py --leak-gate`。
